ABOUT CACHES
============
We have two kinds of caches:
	- c_usercache, c_userlistcache for caching results from user queries 
		> c_usercache stores hit record IDs
		> c_userlistcache list objects -- data used to display tables
	- c_initcache, c_initlistcache for caching anticipated queries that result in high volulme results (>10k)
		> c_initcache stores hit record IDs
      > c_initlistcache list objects -- data used to display tables

CACHING POLICY
==============
	- c_initcache: stores hit record IDs of anticipated queries that can result in 10k or more results
	- c_initlistcache: stores "skinny" list objects for hit record IDs stored in c_initcache
	- c_usercache: stores record IDs from user queries if CANNOT BE FOUND IN c_initcache 
	- c_userlistcache: stores "skinny" list objects for hit record IDs stored in c_usercache

	note: both c_initlistcache and c_userlistcache now contain "skinny" list objects containing
		   small number of proprties. In the past, the old "c_listcache" was storing full body
			list objects and retrieving high volume "full" list objects takes too long for MongoDB.
			In the new strategy, the "skinny" list objects are retrieved much faster and only
			list objects falling on the paging range (specified by offset and limit paramters) are 
			expanded from the source c_list collection. 


CACHE RETRIEVAL WORKFLOW FOR SEARCH APIs
========================================
	- cache_id (md5 digest) is created from payload of a given search API
	- cache_id is searched in c_initcache and c_usercache (in that order)
		> if hit
			$ cache_id is returned
		> if miss
			$ new search is performed and hit record ID list is stored in c_usercache
			$ cache_id is returned

CACHE RETRIEVAL WORKFLOW FOR LIST APIs
========================================
   - listcache_id (md5 digest) is created from payload of a given search API
		> fields in ["offset", "limit", "sort", "order", "columns"] are removed 
		  before making listcache_id
   - listcache_id is searched in c_initlistcache and c_userlistcache (in that order)
      > if hit
         $ list objects retrieved from cache are sorted (using "sort" and "order" paramenters)
			$ list objects within the paging range ("offset" and "limit" parameters) are expanded 
      	$ list objects for page are returned
		> if miss
         $ new list objects are compiled and stored in c_userlistcache
         $ new list objects are sorted (using "sort" and "order" paramenters)
			$ new list objects within the paging range ("offset" and "limit" parameters) are expanded
         $ new list objects for page are returned	


INIT CACHES
===========
The following init advanced searches resulting in hits > 10k records are performed and 
cached in c_initcache and c_initlistcache

	- Glycan (11 cache_id/listcache_id pairs)
		> Empty search
		> Glycan ID Namespace: [GlyTouCan, GNMme, GlyCosmos,PubChem Compound, PubChem Substance,SandBox]
		> Glycan Type: [N-linked, O-linked, Other]
		> Organism: [Human]
	- Protein (18 cache_id/listcache_id pairs)
		> Empty search
		> Organism: [Arabidopsis,Bovine,Cellular slime mold,Chicken,Fruitfly,Hamster,Human,Mouse,Pig,Rat,Zebrafish]
		> Glycosylation Type: [N-linked, O-linked]
		> Glycosylated Amino Acid: [N,T]
		> Glycosylation Evidence Type: [Sites reported with glycans,Predicted sites]
	- Site (18 cache_id/listcache_id pairs)
		> Empty search
		> Amino Acid: [A, D, E, G, I, K, N, P, R, S, T, Y]
		> Annotation Type: [Glycosylation, Glycation, Phosphorylation, SNV, Mutagenesis]



The following init advanced searches resulting in hits < 10k records are performed and 
cached in c_initcache and c_initlistcache
	- Disease (1 cache_id and listcache_id pairs)
		> Empty search
	- Biomarker (1 cache_id and listcache_id pairs)
		> Empty search

For links in the supersearch diagram, init searches are performed and 
cached in c_initcache and c_initlistcache

ADDITIONAL FILTER SPECIFIC LIST OBJECT CACHES
=============================================
For each cached listcache_id in the c_initlistcache, we need additional filter specific
caches. For example, from the listcache_id corresponding to "glycan empty search", we 
have 49 filter specific children listcache_ids:
	
	- by_biomarker_type (4): [diagnostic,monitoring,predictive,prognostic]
	- by_data (4): [Binding,Enzyme,Glycosylation,Publication]
	- by_glycan_type (4): [Glycosphingolipid,N-linked,O-linked,Other]
	- by_mass (7): [0k_1k,1k_2k,2k_3k,3k_4k,4k_5k,5k_0k,no_mass]
	- by_monosaccharide (10): [dhex,hex,hexa,hexn,hexnac,neuac,neugc,other,p,s]
	- by_organism (15): [Arabidopsis,Bovine,Cellular slime mold,Chicken,Fruit fly,Hamster,HCoV-SARS,HCV-H77
						,Human,Mouse,Pig,Rat,SARS-CoV-2,Yeast,Zebrafish]
	- by_sequence_details (5): [BaseComposition, Composition, Fully defined, Incomplete, Topology]
